## 重大（事実と相違）

### 指摘1: 実抽出結果の「検算合格により要確認0件」は事実と異なる
- **該当箇所**: §2.3 見出し「検算に通れば、人の確認は不要になる」／本文「金額の検算（126,850＋10,148＝136,998）に合格したため、人の確認対象から自動的に外れました」／画像キャプション「検算合格で要確認 0 件」
- **問題**: 掲載した実抽出 Run（run_fbab4176）の API 実値を確認したところ、**全6項目の validation は null（検算は発火していない）**。確信度も 0.85〜1.00 のままで、検算合格時の自動引き上げ（0.98 への昇格）の痕跡がない。要確認 0 件になった実際の理由は「全項目の確信度がレビュー基準（標準 0.80）を上回ったため」であり、資料の因果説明は**この画面については虚偽**にあたる。
- **修正**: 見出しを「抽出結果 ― 確認が要るものだけが人に残る」に変更。本文・キャプションを「すべての項目の確信度がレビュー基準を上回ったため要確認 0 件」という実際の因果に書き換え。検算・自動引き上げは §3.2 で機能説明として維持（実装は確認済み: orchestrator validate ノードに auto-elevation 実装あり）。
- **製品側への申し送り（資料外）**: quotation スキーマの実抽出で V-SUM 系検算が発火していない。項目名と検算対象のマッピング（subtotal_amount / tax_amount / total_amount）が quotation で機能しているか確認を推奨。

## 中（誇張・過大の恐れ）

### 指摘2: 「根拠が3つ揃って初めて提案される」は制約の過大表現
- **該当箇所**: §3.1
- **問題**: 実装上の自動提案条件（DD-10）は「混同文字表に該当」**または**「過去の修正例に一致」。V-SUM 一致は提案の**必要条件ではなく傍証**。3条件すべてが必須であるかのような記述は、実際より強い保証を示唆する。
- **修正**: 「この提案には3つの根拠が併記されている」とし、提案条件は「混同文字表への該当、または過去修正例への一致に限られ、検算結果などの傍証とあわせて明示される」と正確化。

### 指摘3: 「画面改修やフォーマット変更の影響を受けません」は範囲が広すぎる
- **該当箇所**: §5 冒頭
- **問題**: RPA 比較の文脈だが、「フォーマット変更の影響を受けない」は**帳票フォーマットが変わっても読み取りに影響しない**とも読め、読取品質への影響（当然あり得る）を否定する誇張になる。
- **修正**: 「連携先の画面改修で自動化が壊れる、という画面操作型 RPA 特有の障害が構造的に起きません」に限定。

### 指摘4: 「有効化は dry-run 成功が前提条件」は適用範囲が実装より広い
- **該当箇所**: §5.1 ②
- **問題**: 実装（gateway routers）で dry-run 成功が有効化の前提になるのは **DB 格納（db_write）を含むグラフのみ**。全ワークフロー一律の前提であるかのような記述は過大。
- **修正**: 「DB 格納を含む図は、dry-run の成功が有効化の前提条件」に限定。

### 指摘5: クラウドストレージ連携を無条件の提供機能として提示
- **該当箇所**: §2.1・§5.2（Google Drive / Microsoft 365 / Box 連携）
- **問題**: 連携機能は実装済み・E2E 検証済みだが、**実クレデンシャルでの OAuth 総合検証が未了**（検証はテスト用プロバイダ）。エンタープライズ向け資料として、提供条件の留保なしの断定は過大。
- **修正**: §5.2 に「クラウドストレージ連携は最終検証中の機能を含みます。ご利用環境での提供条件・時期は個別にご案内します」を追記。

### 指摘6: 「基盤モデルの追加学習には使いません」の断定は裏取り未了
- **該当箇所**: §11 FAQ
- **問題**: 抽出・補正に外部 LLM API を利用しており、**学習利用の有無は提供事業者の規約・契約形態に依存**する。無条件の断定は、規約確認（裏取り）なしにはエンタープライズ品質の記述として不十分。
- **修正**: 「お客様データを基盤モデルの追加学習に利用しない構成の LLM を採用します。利用モデルとデータ取り扱い条件は、ご契約時に書面で明示します」に変更（構成としての方針＋契約時明示に置き換え）。
- **申し送り（資料外）**: 採用 LLM プロバイダの最新規約文言の確認と、契約書式への反映が必要。

## 軽（正確性・整合）

### 指摘7: スキーマ項目数の誤記
- **該当箇所**: 補足A 画像キャプション「invoice v6（17項目）」
- **問題**: 実環境 API の実値は **16項目**。
- **修正**: 「invoice v6（16項目）」に訂正。

### 指摘8: 確信度バー「青（検算合格）」の断定
- **該当箇所**: §3 箇条書き
- **問題**: 実画面では検算未発火の確信度 1.00 項目も青表示されており、「青＝検算合格」の断定は実挙動と不整合。
- **修正**: 「青（最高確信・検証済み）」に変更。

### 指摘9: 「同じスキーマで読めます」の保証含意
- **該当箇所**: §2 冒頭
- **問題**: 「読めます」はレイアウト非依存の読取成功を保証すると読める。テンプレートレスの正しい主張は「取引先ごとの追加登録が不要」であり、精度は帳票依存（FAQ でも PoC 実測と明言している）。
- **修正**: 「同じスキーマをそのまま使えます（取引先ごとの追加登録は不要です）」に変更。

### 指摘10: 免責表記の欠落
- **該当箇所**: 巻末
- **問題**: 機能・提供条件が変わり得る段階の資料として、時点明示と変更可能性の免責がない（エンタープライズ配布資料の標準要件）。
- **修正**: 巻末に「本資料の記載内容は2026年8月時点のものです。機能・提供条件は予告なく変更される場合があります。」を追記。
