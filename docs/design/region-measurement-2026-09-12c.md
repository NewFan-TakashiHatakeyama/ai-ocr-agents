**既定 on を維持する**と決めたうえで、その 1 件の穴を塞ぐ改善を測った。

## 別データでの検証（計測の前に）

同じデータ（sample2 ← sample13）で規則を決めると過適合になるので、検出器は
**sample13 の 3 件を見ずに書ける一般規則**として作り、次の順で検証した。

1. **正解値 29 帳票**（`golden/data/samples_ground_truth.json`）: 該当するのは sample13 の
   3 項目だけ。「【サンプル】ビズリフォーム株式会社」「サンプル商事株式会社」
   「東京都新宿区高田馬場XX-X-XX新宿ビルX階」「名古屋市中区○-○-○○○生命ビル12F」
   「sample.Inc」は紙面にそう印字された値なので通る。
2. **第 4 回の S2 / S3 の例示値 94 件**（`region_from_gold` が起こした「見出し語＋値」の形。
   `golden/data/region_ab_example_values.json` に固定）: sample2 ← sample13 の 3 件だけ。
   S1 は例示値を落として回す（設計 §3）ので**この変更は S1 に届かない**。S2 の 29 件にも
   該当が無いので **S2 にも届かない**。届くのは S3 の 1 テンプレート（3 項目）だけ。
3. **独立に作った held-out 463 件**: 検出器の規則を見せずに、4 つの観点（日本語の記入例語
   130 件／紛らわしい実値 133 件／見出し語＋値 120 件／英語混在 80 件）で別々に生成させた
   文字列に「落とすべき／通すべき」の期待値を付けたもの（生成と判定は LLM エージェント、
   食い違いの原因特定は別のエージェントがコードを読んで行い、最終判断は人が確認した）。結果:

| レンズ | 件数 | 実値の誤検知（通すべきを落とした） | 見逃し（落とすべきを通した） |

## 結果: S3 の測り直し（12 件 × 5 試行、両アーム交互）

S1 / S2 は変更が届かない（上記 2）ので回し直さず、第 4 回サイクル 1 の出力をゲート判定に
そのまま使う。S3 だけを `--arms s3` で両アーム交互に全件回した（対照も回し直している。
対照の再利用はしていない）。

出力: `golden/out/phase4r5/c1/s3_ab.json`（`scoring: address_jp`、対 60 / 60。sample13 ← sample2 の
試行 4 の介入が LLM 側の失敗で落ち、`--resume` で**その 1 対だけ**埋めた。対照の再利用なし）。

| | 対照 | 介入 | McNemar（全項目） | McNemar（位置依存のみ） |
|---|---|---|---|---|
| S3（12 × 5） | 0.789 | **0.834** | 対照のみ 6 / 介入のみ 22 / p = 0.004（介入が有意に良い） | 6 / 20 / p = 0.009 |

第 4 回サイクル 3（同じ帳票、対照 0.797 / 介入 0.806、11 / 14 の引き分け）と比べて、
介入側だけが動いた。帳票ごと（対照 → 介入、5 試行の対。第 4 回サイクル 3 を併記）:

| 帳票 | 第 5 回 | 純増減 | 第 4 回 c3 | ヒント given / dropped / followed / rejected |
|---|---|---|---|---|
| sample12 ← sample17 | 24/30 → 25/30 | +1 | +1 | 25 / 0 / 20 / 5 |
| sample17 ← sample12 | 25/35 → 25/35 | ±0 | ±0 | 15 / 10 / 15 / 0 |
| sample16 ← sample19 | 25/30 → 25/30 | ±0 | ±0 | 5 / 20 / 0 / 5 |
| sample19 ← sample16 | 23/25 → 25/25 | +2 | −2 | 0 / 25 / 0 / 0 |
| **sample2 ← sample13** | 21/35 → 21/35 | **±0** | **−6** | 5 / 20（うち `placeholder_example` 15）/ 0 / 5 |
| sample13 ← sample2 | 21/25 → 24/25 | +3 | +3 | 15 / 5 / 0 / 10 |
| sample27 ← sample29 | 20/30 → 25/30 | +5 | +3 | 10 / 20 / 0 / 6 |
| sample29 ← sample27 | 19/30 → 19/30 | ±0 | +1 | 5 / 25 / 2 / 3 |

- **sample2 ← sample13 の害は消えた**（−6 → ±0）。issuer_name / customer_name / issuer_address の
  例示値が 5 試行とも `placeholder_example` で落ち、渡ったのは document_no（候補「350」、
  例示値「見積番号 MI0001」）だけで、それも 5 試行とも rejected（従わなかった）。項目ごとに
  見ると issuer_name 対照 3/5 → 介入 3/5、issuer_address 3/5 → 3/5、customer_name 0/5 → 0/5、
  customer_address 0/5 → 0/5、他 3 項目 5/5 → 5/5 で**全項目が対照と同じ**（落とすと対照に
  戻る、という非対称性の前提どおり）。
- 帳票ごとの純増減は最小 ±0（G2 の下限 −2 を破る帳票なし）。第 4 回で −2 だった
  sample19 ← sample16 / sample19 ← sample4 は今回 +2 / +1 で、どちらもヒントは全部
  落ちている（no_spans 20 / kind_conflict 5、渡っていない）ので、差は Gemini の揺れ。
- S3 全体で介入が有意に良くなったのは、別雛形でも一部の項目は同じ位置にあって
  （sample27 ↔ sample29 の issuer_address 0/5 → 5/5、sample13 ← sample2 の issuer_name
  1/5 → 4/5）ヒントが効いたため。「間違ったテンプレートでも壊れない」が G2 の要求で、
  「良くなる」ことまでは求めていない。
- 介入アームのヒントの内訳（60 run）: given 110、followed 37、partial 5、rejected 64、
  no_evidence 4、dropped 185（no_spans 130 / kind_conflict 40 / **placeholder_example 15**）。
  別雛形なので候補 0 件が最多で、渡っても 6 割は捨てられている（反証可能なヒントの
  設計どおり）。

## 判定（第 5 回）

判定は **S1・S2 = 第 4 回サイクル 1**（変更が届かないので回し直さない。「別データでの検証」2）、
**S3 = 第 5 回**。ゲート判定スクリプトの出力は `golden/out/phase4r5/c1/gates.md`。

| ゲート | 判定 | 根拠 |
|---|---|---|
| G1 | ✅ | S1（21 × 5）8 / 72 / p < 0.001（第 4 回サイクル 1 と同じ） |
| G2 | ✅ | S3 McNemar 6 / 22 / p = 0.004（介入が有意に良い。「有意に悪くない」を満たす）。**帳票ごとの純増減の最小は ±0**（第 4 回は sample2 ← sample13 の −6 で落ちていた） |
| G3 | ✅ | sample8 の customer_name を 5/5 `kind_conflict` で守った（第 4 回サイクル 1 と同じ） |
| G4 | ✅ | S3 で落とした／捨てた 249 対: 対照 201 / 介入 215、McNemar 6 / 20 / p = 0.009（介入が有意に良い） |
| G5 | ✅ | 領域なしプロンプトのスナップショット一致（プロンプト不変） |
| G6 | ✅ | プロンプトは第 3 回・第 4 回と同じ |

**6 ゲート全通過。** 第 4 回で唯一落ちていた G2 の帳票単位の条件は、記入例語の例示値を
落とす（渡さない）だけで通った。ヒントの機構・プロンプトは変えていない。

既定 on は維持（ユーザー判断、2026-09-12）。この改善で「間違ったテンプレートを当てても
1 帳票も壊れない」が、手元の 12 件では成り立つ。

## 計測の限界

- S3 の対照は第 4 回サイクル 3 と同じ帳票・同じプロンプトだが、時間帯が違うので
  帳票ごとの対照の値は動く（Gemini の揺れ）。改善の判断は**同じ試行の対照との対**で行い、
  第 4 回との比較は参考に留める。
- 記入例の帳票は評価データに sample13 の 1 枚しか無い。検出器の一般性は held-out 463 件と
  コードレビューで担保したが、実帳票での再現は 1 テンプレート分しか測れていない。
  golden 100 件の受領後に、記入例・白紙雛形由来のテンプレートを加えて測り直す。
