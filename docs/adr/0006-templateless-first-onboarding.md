# ADR-0006: 帳票登録はテンプレートレス先行（抽出→テンプレート化）に順序を反転する

- 状態: Accepted
- 日付: 2026-08-22

## 背景

従来の帳票登録フロー（①取込〜⑩有効化）は、実装上「③スキーマ登録が先、①取込が後」を
UI が強制していた:

- チャットに画像を貼る → アップロード → `/documents/{id}` へ誘導
- 未抽出の帳票画面（ExtractStart）は**スキーマ選択が必須**で、未選択だと
  「抽出を開始」ボタンが押せない
- スキーマが 1 つも無いテナントでは選択肢が「（スキーマ未登録）」のみ＝**行き止まり**
- スキーマが有っても、推定が付かない帳票は**先頭スキーマへ強制割当**され、
  無関係な定義（例: 請求書スキーマで納品書を抽出）で誤抽出が走っていた

これは利用実態と逆である。新しい帳票種を初めて取り込む時点では、
**どんな項目がその帳票にあるか自体がまだ分かっていない**。空欄から項目名を
発明させるより、実物から抽出された値を見ながら「残す項目」を選ばせる方が、
定義の質も導入の速度も上がる。プロダクトの標榜（テンプレートレス AI-OCR）とも
これで一致する。永続層は元々 schema_id を nullable にしており
（`pg_persistence.EMPTY_SCHEMA` の注記「テンプレートレス既定」）、
UI と KIE プロンプトだけが順序を逆に強制していた。

## 決定

**「まず取り込んで抽出 → 値を見てからテンプレート化」を既定の導線にする。**

1. **スキーマ選択を任意にする**（ExtractStart）。既定は
   「ユーザー選択 > 自動分類の推定 > スキーマなし（自動発見）」。
   先頭スキーマへの強制割当は廃止する。
2. **KIE プロンプトに自動発見モードを追加する**。スキーマの fields が空のとき、
   LLM は帳票に実在する「見出し語＋値」の組を自ら発見して抽出する
   （name は snake_case、label に見出し原文、span 根拠の契約は通常時と同一）。
3. **発見された label を `extraction_fields.label`（migration 0006）へ永続化する**。
   スキーマ指定の抽出は従来どおり field_schemas から label を引き、行の label は
   スキーマレス時のフォールバックとしてのみ使う。
4. **結果 API（GET /documents/{id}/result）に `schema_id` を追加する**。
   null＝スキーマレス抽出であり、UI はこれで「テンプレート化」導線を出し分ける。
5. **検証画面にテンプレート化ダイアログを追加する**。抽出結果の項目一覧から
   残す項目を選び（値が取れなかった項目は既定で除外）、label / name / 型
   （値の見た目から初期推測）を調整して `PUT /schemas`（create=true, admin）で
   スキーマ v1 を作る。以後の同種帳票は分類（⑦）がこのスキーマを提案する
   — ただし現状の分類は「アップロード時の doc_type 宣言」か「ファイル名の語彙一致」
   だけが信号であり、チャット貼り付け（doc_type 無指定）では提案が付かないことが
   多い。その場合も自動発見で抽出は成立し、抽出画面のプルダウンから作成済み
   スキーマを選べる。**本文内容ベースの分類（発見 label とスキーマ label の照合）は
   別チケット**とし、それまではテンプレート化の成功メッセージで
   「次回はファイル名に種別を含めるか、種別を指定して取り込む」ことを案内する。

## 影響

- **既存のスキーマ指定フローは不変**。スキーマがあるテナントでは分類の提案が
  従来どおり既定になり、抽出結果・正規化・確信度ゲートの動作も変わらない。
- **スキーマレス抽出の正規化・ゲートは保守的**。型情報が無いので
  deterministic_normalize は string 扱い、critical 閾値は付かない（standard 閾値 +
  grounding 必須はそのまま効く）。値の型による検証はテンプレート化後の
  次回抽出から効き始める。これは意図的な段階設計である。
- **プロンプトバンドル 2026.07-1 を上書き更新した**。スキーマ指定時の指示文は
  変えていない（自動発見の節は「fields が空の場合」に限定）。ゴールデン回帰
  （スキーマ指定で走る）で無影響を確認する。バンドルの版管理を厳密に運用する
  段階になったら新版ディレクトリを切ること。
- **migration 0006** は nullable 列の追記のみ。migrate → サービス更新の通常順序で
  安全（旧コードは列を無視、新コードは migrate 後に起動する）。
- テンプレート化は admin 限定（PUT /schemas の既存権限）。reviewer にはバナーで
  案内のみ出す。

## やらないこと

- **抽出の自動開始**（アップロードと同時に抽出）: LLM コストが掛かる操作は
  明示クリックに残す。ワークフロー（⑤⑥自動取込）では従来どおり自動で走る。
- **テンプレート化直後の自動再抽出**: 作成したスキーマでの取り直しは利用者の
  判断（既存の再抽出導線）に委ねる。
- **明細（tables）のテンプレート化**: v1 はヘッダ項目（fields）のみ。
  line_items の列定義化は別チケット。
